* Introduction

In most presentations of Riemannian geometry, e.g. [cite/t:@o1983semi] and [[https://en.wikipedia.org/wiki/Fundamental_theorem_of_Riemannian_geometry][Wikipedia]],
the fundamental theorem of Riemannian geometry ("the miracle of
Riemannian geometry") is given: that for any semi-Riemannian manifold
there is a unique torsion-free metric connection. I assume partly
because of this and partly because the major application of Riemannian
geometry is General Relativity, connections with torsion are given
little if any attention.

It turns out we are all very familiar with a connection with torsion:
it is hidden in the Mercator projection. Some mathematical physics
texts, e.g. [cite/t:@Nakahara2003], allude to this but leave the
details to the reader. Moreover, this connection respects the metric
induced from Euclidean space (in fact we will construct it so it does
this).

We will construct the connection by declaring the compass directions,
due south and due east, to be parallel. Such a connection cannot exist
on the entire sphere: at the poles the compass directions make no
sense, since due south at the North Pole would have to point down
every meridian at once. The [[https://en.wikipedia.org/wiki/Hairy_ball_theorem][hairy ball theorem]] says this is
unavoidable: there is not even a single nowhere-vanishing vector field
on \(S^2\), let alone a frame (a set of vector fields which form a
basis of the tangent space at each point). The compass frame, and with
it the connection, lives on the sphere minus the two poles but for
convenience we restrict it a bit further. We will work on the familiar
spherical coordinate chart: \(\theta\) the angle from the North Pole
and \(\phi\) the longitude, measured from the prime
meridian. Furthermore it will turn out that this connection no
curvature (another reason it could not be extended to the whole
sphere.

Note: the observant reader might be wondering how we can define
directions without first defining a connection. We do that using the
round sphere metric.

* Koszul Connections

A connection allows us to say what a straight line is: a curve which
never changes direction, so that its velocity is parallel to
itself. On the sphere with the usual round (Levi-Civita) connection
the straight lines are great circles; for the connection in this post
they are the curves of constant compass bearing, the so-called rhumb
lines, which appear as straight lines on a Mercator map.

FIXME: Add links for both definitions.

Most textbooks define a *Koszul connection* on a vector bundle \(E \to
M\) to be a map \(\nabla : \mathfrak{X}(M) \times \Gamma(E) \to
\Gamma(E)\), \((X, \sigma) \mapsto \nabla_X \sigma\), such that

it is \(C^\infty(M)\)-linear in \(X\):

\[
\nabla_{fX + Y}\sigma = f\,\nabla_X\sigma + \nabla_Y\sigma
\]

it is additive in \(\sigma\):

\[\nabla_X(\sigma + \tau) = \nabla_X\sigma + \nabla_X\tau\]

and it satisfies Leibniz in \(\sigma\):

\[\nabla_X(f\sigma) = (Xf)\,\sigma + f\,\nabla_X\sigma\]

FIXME: Note that Mathlib curries on the section rather than on the direction:
\(\nabla\sigma\) is the partial application, not \(\nabla_X\). This is
the right choice for a pointwise definition, since \(\nabla\sigma\) is
linear over functions in the direction and so is a genuine section of
\(\mathrm{Hom}(TM, E)\), whereas \(\nabla_X\) obeys a Leibniz rule in
\(\sigma\) and is a differential operator.

The *[[https://leanprover-community.github.io/mathlib4_docs/Mathlib/Geometry/Manifold/VectorBundle/CovariantDerivative/Basic.html#IsCovariantDerivativeOn][Mathlib connection]]*
is a map \(\nabla : \Gamma(E) \to
\Gamma(\mathrm{Hom}(TM, E))\), \(\sigma \mapsto (x \mapsto
(\nabla\sigma)(x))\), where here \(\Gamma\) means all sections, not
only smooth ones. That is, Mathlib assigns to each section
\(\sigma\) and point \(x\) a continuous linear map \((\nabla\sigma)(x) :
T_xM \to E_x\) such that,
for points \(x\) of a given set \(s\), and sections \(\sigma, \tau\)
and functions \(g\) differentiable at \(x\):
\[\nabla(\sigma + \tau)(x) = \nabla\sigma(x) + \nabla\tau(x)\]

\[\nabla(g\sigma)(x) = g(x)\,\nabla\sigma(x) + dg_x \otimes \sigma(x)\]

where

\[(dg_x \otimes \sigma(x))(v) = dg_x(v)\,\sigma(x)\]

Every Mathlib connection gives a textbook one, by setting
\((\nabla_X\sigma)(x) = (\nabla\sigma)(x)(X(x))\). In finite dimensions
the converse also holds: a bump-function argument shows that linearity
over the smooth functions forces \((\nabla_X\sigma)(x)\) to depend only
on the vector \(X(x)\), linearly, and that linear map is
\((\nabla\sigma)(x)\). Mathlib's definition is the more restrictive
one, and it says directly what a connection is for: differentiating a
section at a point in the direction of a tangent vector.

Given a curve \(\gamma\) and a vector field \(V\) defined on an open
set containing it, then if at every point of the curve:

\[
(\nabla V)(\gamma(t))\big(\gamma'(t)\big) = 0
\]

we say \(V\) is *parallel* along \(\gamma\): as we move along \(\gamma\), \(V\) does
not change, in the sense that the connection defines. Only the values
of \(V\) on the curve matter, and given a starting vector \(v\) at
\(\gamma(0)\) there is exactly one parallel \(V\) along \(\gamma\) with
\(V(0) = v\) (by the existence and uniqueness of solutions to linear
ODEs); its values are the *parallel translates* of \(v\).

For the flat connection \(\nabla_{\gamma'}\gamma'\) is just the ordinary second derivative, i.e. the acceleration.
Take a circle of radius \(r\) traversed at unit speed:
\[
\gamma(t) = r\big(\cos(t/r),\ \sin(t/r)\big), \qquad
\gamma'(t) = \big(-\sin(t/r),\ \cos(t/r)\big),
\]
\[\nabla_{\gamma'}\gamma' = \gamma''(t) = -\frac{1}{r}\big(\cos(t/r),\ \sin(t/r)\big).\]
This vector points to the centre and has length \(1/r\), which is the curvature of the circle. It is never zero, because the circle keeps changing direction, so it isn't a straight line. As \(r \to \infty\) it tends to \(0\), matching the circle flattening out into a line.

In our (finite dimensional) setting, recall that a /frame/ on an open
set \(U\) is a collection of vector fields \(e_1, \ldots, e_n\) on
\(U\) which form a basis of the tangent space \(T_xM\) at each point
\(x\) of \(U\). Every frame comes with a dual /coframe/: covector
fields \(\varepsilon^1, \ldots, \varepsilon^n\) with
\(\varepsilon^i(e_j) = \delta^i_j\), so that any tangent vector can be
written \(v = \sum_i \varepsilon^i(v)\, e_i\). The coordinate vector
fields of a chart give a frame on the chart's domain; the compass
frame is another.

A frame is carried in parallel along a curve if each of its vectors is
parallel along the curve: loosely, the frame is carried along without
turning
But what counts as "turning" is exactly what the connection decides.
For the Mercator connection, not turning means keeping the same
compass bearing, so a frame carried along a circle of latitude does
not turn. For the Levi-Civita connection, not turning means not
rotating about the normal to the sphere. This is what the swing of a
Foucault pendulum does, and by that standard it is the compass
directions on the ground that turn, which is why the pendulum appears
to precess. More on this in a future blog.

The domain of the chart is the sphere with both poles and one
half-meridian removed:

If \(\psi : U \to \mathbb{R}^2\) is the chart map, where \(U\) is the
domain above, then
\[
\psi^{-1}(\theta, \phi) = (\sin\theta\cos\phi,\ \sin\theta\sin\phi,\ \cos\theta),
\]
with \(\theta \in (0, \pi)\) the angle from the north pole and
\(\phi \in (-\pi, \pi)\) the longitude, and we write
\(\theta := \pi^1 \circ \psi\) and \(\phi := \pi^2 \circ \psi\) for the
coordinate functions. NB this is just a chart, not the Mercator
projection.

The round metric, the one induced from \(\mathbb{R}^3\), is
\[
g = d\theta^2 + \sin^2\theta \, d\phi^2 .
\]
With the Levi-Civita connection of this metric the straight lines,
that is the geodesics, are great circles, and any two great circles
meet (twice): there are no parallel lines in Euclid's sense. Instead
let us change what parallel means: two tangent vectors, at different
points, are parallel if they have the same compass bearing, that is,
if they make the same angle with the meridians through their points.

For a bearing to make sense we must have some concept of direction. Recall
the metric at a point is an inner product \(g_x\) on the tangent space
\(T_xS^2\), and the angle between nonzero \(v, w\) is defined by

\[
\cos\angle_x(v,w)=
\frac{g_x(v,w)}
{\sqrt{g_x(v,v)}\sqrt{g_x(w,w)}}.
\]

A bearing south is \(\partial_\theta\) (since \(\theta\) is the angle
from the North Pole) and the angle \(\angle_x(\partial_\theta, v)\) of
a vector \(v\) to the meridian is its bearing, measured from south, with

\[
\cos\angle_x(\partial_\theta,v) = \frac{g_x(\partial_\theta, v)}{\sqrt{g_x(v,v)}},
\]

so we should take that as the first vector of our frame,
\(e_1 = \partial_\theta\), which is a unit vector since
\(g(\partial_\theta, \partial_\theta) = 1\). If the frame is to be
orthonormal, the metric then forces \(e_2\) up to sign: since
\(g(\partial_\theta, \partial_\phi) = 0\) and
\(g(\partial_\phi, \partial_\phi) = \sin^2\theta\), we must have
\(e_2 = \pm(1/\sin\theta)\,\partial_\phi\), and we choose the plus
sign, which points due east.

* Connections from Coefficients in a Frame

The key idea is this: two vectors should be parallel exactly when
they have the same components in the compass frame, that is, the same
bearing and the same length. A vector field of length \(\ell\) and
bearing \(\alpha\), measured from south, is
\[
V = \ell(\cos\alpha\, e_1 + \sin\alpha\, e_2),
\]
with \(\ell\) and \(\alpha\) constant, and we want every such field to
be parallel along every curve \(\gamma\). Since its components are
constant, the Leibniz rule gives

\[
(\nabla V)(\gamma(t))(\gamma'(t))
= \ell\big(\cos\alpha\, (\nabla e_1)(\gamma(t))(\gamma'(t)) + \sin\alpha\, (\nabla e_2)(\gamma(t))(\gamma'(t))\big)
\]

and for this to vanish for every bearing we need
\(\nabla e_1 = \nabla e_2 = 0\).

In SageManifolds we can just say =nabla.add_coef(e)= to specify a
covariant derivative by its connection coefficients \(\Gamma\) relative to a
frame \(e\) with dual coframe \(\varepsilon\), supported on a set \(s\). Well the
coframe and the valid set do not need to specified: in SageManifolds, \(e\) is a structure which
includes the domain and the coframe is determined by the frame. NB the connection coefficients are
all set to the default 0 in =nabla.add_coef(e)=.

No such help is available in Mathlib but we can construct a connection via its coefficients ourselves.

Let \(\nabla\) be a connection in the sense of Mathlib, as above. Its
Leibniz rule, applied to a tangent vector \(v \in T_xM\), reads
\[
(\nabla(f\sigma))(x)(v) = df_x(v)\,\sigma(x) + f(x)\,\big((\nabla\sigma)(x)(v)\big)
\]

Given a frame \(e_1, \ldots, e_n\) on \(U\) with coframe
\(\varepsilon^1, \ldots, \varepsilon^n\), define the connection
coefficients \(\Gamma^i_{jk}\), functions on \(U\), by
\[
(\nabla e_k)(x)\big(e_j(x)\big) \triangleq \sum_i \Gamma^i_{jk}(x)\, e_i(x).
\]
Write the components of a section \(\sigma\) as functions
\(\sigma^k := \varepsilon^k(\sigma)\), that is
\(\sigma^k(y) = \varepsilon^k_y(\sigma(y))\), so that
\(\sigma = \sum_k \sigma^k e_k\), and, for \(x \in U\) and
\(v \in T_xM\), the components of \(v\) as numbers
\(v^j := \varepsilon^j_x(v)\), so that \(v = \sum_j v^j e_j(x)\).

Additivity and then the Leibniz rule give
\[
(\nabla\sigma)(x)(v) = \sum_k (\nabla(\sigma^k e_k))(x)(v)
= \sum_k \Big( d\sigma^k_x(v)\, e_k(x) + \sigma^k(x)\, (\nabla e_k)(x)(v) \Big),
\]
and linearity of \((\nabla e_k)(x)\) gives
\[
(\nabla e_k)(x)(v) = \sum_j v^j\, (\nabla e_k)(x)\big(e_j(x)\big)
= \sum_{i,j} \Gamma^i_{jk}(x)\, v^j\, e_i(x).
\]
Substituting and relabelling,
\[
(\nabla\sigma)(x)(v) = \sum_i \Big( d\sigma^i_x(v) + \sum_{j,k} \Gamma^i_{jk}(x)\, \sigma^k(x)\, v^j \Big)\, e_i(x).
\]

Conversely, any choice of functions $\Gamma^i_{jk}$ on $S$ makes this formula a
connection in Mathlib's sense: additivity is immediate and the Leibniz rule is a
one-line check; so on $S$, connections correspond exactly to the connection
coefficients relative to the frame.

We can write this definition for the specific case of \(S^2\) in Lean as:

#+begin_src lean4 :tangle MercatorConnection/Posts/MercatorVPostCode.lean
  open Classical in
  def covDerivOfFrame (s : Set S2)
      (e : Fin 2 → Π x : S2, TangentSpace (𝓡 2) x)
      (ε : Fin 2 → Π x : S2, TangentSpace (𝓡 2) x →L[ℝ] ℝ)
      (Γ : Fin 2 → Fin 2 → Fin 2 → S2 → ℝ) :
      (Π x : S2, TangentSpace (𝓡 2) x) →
      (Π x : S2, TangentSpace (𝓡 2) x →L[ℝ] TangentSpace (𝓡 2) x) :=
    fun σ x =>
      if x ∈ s then
        ∑ i, ((mvfderiv (𝓡 2) (fun y ↦ ε i y (σ y)) x)
            + ∑ j, ∑ k, (Γ i j k x * ε k x (σ x)) • ε j x).smulRight (e i x)
      else 0
#+end_src

I find the lifted form a bit hard to parse and this made it clearer to me:

#+begin_src lean4 :tangle MercatorConnection/Posts/MercatorVPostCode.lean
lemma covDerivOfFrame_apply (hx : x ∈ s) (v : TangentSpace (𝓡 2) x) :
    covDerivOfFrame s e ε Γ σ x v =
      ∑ i, (mvfderiv (𝓡 2) (fun y ↦ ε i y (σ y)) x v
        + ∑ j, ∑ k, (Γ i j k x * ε k x (σ x)) * ε j x v) • e i x := by
  simp [covDerivOfFrame, hx]
#+end_src

* The Coordinate Expression

In the compass frame all the coefficients of =mercatorCov= are zero.
In the coordinate frame \(\{\partial_\theta, \partial_\phi\}\) they
are not: there is exactly one nonzero coefficient,
\(\Gamma^\phi_{\theta\phi} = \cot\theta\), which is what
SageManifolds displayed. (SageManifolds writes it as
\(\Gamma^\phi_{\phi\theta}\): its convention is
\(\nabla_{e_j} e_i = \Gamma^k_{ij}\, e_k\), with the direction index
last, whereas ours puts it first. It is the same coefficient.)

The coefficients in the coordinate frame, as an array:

#+begin_src lean4 :eval yes :results output :exports results :wrap example
import MercatorConnection.MercatorGeom
#print cotθ
#print Γmercator
#+end_src

#+RESULTS:
#+begin_example
def cotθ : ↑S2 → ℝ :=
fun x => Real.cos (θ_coord x) / Real.sin (θ_coord x)
def Γmercator : Fin 2 → Fin 2 → Fin 2 → ↑S2 → ℝ :=
fun i j k x => if i = 1 ∧ j = 0 ∧ k = 1 then cotθ x else 0
#+end_example

And we can check that this really does give the same frame independent
covariant derivative as the one in the compass frame: Expanding
=mercatorCov= in the coordinate frame:

#+begin_src lean4 :eval yes :results output :exports results :wrap example

#+end_src

#+RESULTS:
#+begin_example
mercatorCov_coord' : ∀ (σ : (y : ↑S2) → TangentSpace (modelWithCornersSelf ℝ (EuclideanSpace ℝ (Fin 2))) y) {x : ↑S2},
  x ∈ sphSource →
    MDiffSectionAt σ x →
      covDerivOfFrame sphSource ![e₁, e₂] ![ε₁, ε₂] 0 σ x = covDerivOfFrame sphSource ![Xθ, Xφ] ![dθ, dφ] Γmercator σ x
#+end_example

Under a change of frame \(e^\prime_i = A^j_i e_j​\) the connection
coefficients transform inhomogeneously,

\[
\Gamma^\prime = A^{−1}\Gamma A + A^{−1}dA
\]

because connection coefficients are not the components of a tensor, the second term being the
non-tensorial part: it is the Maurer–Cartan
form \(g^{-1}dg\) of \(GL(2)\) pulled back along \(A\).

Here the change from the compass frame \(\{e_1, e_2\}\) to the
coordinate frame \(\{\partial_\theta, \partial_\phi\}\) has
\(A = \mathrm{diag}(1, \sin\theta)\), so with \(\Gamma = 0\) on the
compass side the entire coordinate expression comes from the
inhomogeneous term:
\[
A^{-1}dA = \mathrm{diag}(0,\, \cot\theta\, d\theta),
\]
i.e. the single symbol \(\Gamma^\phi_{\theta\phi} = \cot\theta\),
exactly what =mercatorCov_coord= computes. I hope to make the
transformation law itself, and its formalisation via the Yang–Mills
transformation law on the frame bundle, the subject of a future post.
